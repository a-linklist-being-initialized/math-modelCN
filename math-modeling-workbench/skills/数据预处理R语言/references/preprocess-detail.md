# 数据预处理（R 语言）——10 步详细执行规范

> 本文件是 `SKILL.md` 的详细执行层，**开始执行前必须实际读取本文件**。SKILL.md 只保留大纲与硬规则。
> 通用输入输出约定：输入文件只读；输出统一写入 `results/数据预处理结果/` 与 `figures/数据预处理/`；CSV 一律 UTF-8 with BOM（R 中先写无 BOM 临时文件再前置 EF BB BF 字节，或写 `\ufeff` 头）。

## 每步通用结构

每一步必须覆盖：**目标 / 必做动作 / R 代码要点 / 配图要求 / 表格输出 / 场景依据 / 验收**；涉及取舍的步骤额外包含**决策点（交互停顿）**。

## 第 1 步：数据分布情况（直方图、箱线图等）

- **目标**：刻画每个数据文件核心变量的分布形态（偏度、峰度、多峰、离群尾部），为后续变换/分组/异常处理提供事实依据。
- **必做动作**：对数值列做直方图；对分类×数值组合做箱线图（如按任务类型/区域/时段分面）；时间序列列加时序折线图；输出每列偏度/峰度诊断表。
- **R 代码要点**：`ggplot2` 直方图 + `geom_boxplot`；分面 `facet_wrap`；中文标题。
- **配图要求**：每张图"前"视角（原始分布），至少覆盖所有核心数值列；建议同图双面板对比不同分组。
- **表格输出**：`step1_分布诊断_偏度峰度.csv`。
- **场景依据**：分布形态决定第 4 步是否变换（右偏→log/Box-Cox）、第 5 步编码必要性、第 8 步标准化选择。
- **验收**：每个核心数值列至少 1 图；偏度/峰度表与图一致。
- **决策点**：无需停顿；若某列分布形态特殊（双峰/极重尾），记录观察，交第 3、4 步决策。

## 第 2 步：描述性统计与交叉表

- **目标**：给出全表统计画像与分类变量交叉结构。
- **必做动作**：对连续列输出 n/缺失/均值/SD/四分位/中位数/偏度/峰度；对分类变量两两做交叉表（`table`/`pivot_wider`），并按分组输出组内统计。
- **R 代码要点**：`dplyr::summarise` + `table` + `tidyr::pivot_wider`。
- **配图要求**：交叉表热力图或分组柱状图（每张交叉表至少 1 图）。
- **表格输出**：`step2_描述统计_*.csv`、`step2_交叉表_*.csv`。
- **场景依据**：交叉表验证业务结构（如任务类型×区域与区域定位一致）；描述统计支撑论文"数据概况"段落。
- **验收**：描述统计列齐全；交叉表无缺失组合遗漏。
- **决策点**：无需停顿。

## 第 3 步：数据清洗（缺失值、异常值、一致性）

- **目标**：识别并决策缺失值填补与异常值删除/保留，并做跨表一致性校验。
- **必做动作**：
  - 缺失：全表缺失统计；写明缺失机制假设（MCAR/MAR/MNAR 依据）；缺失>0 时按类型决策（数值中位数/插值/多重插补 MICE；分类众数），并报告填补量；
  - 异常：IQR 规则 + **MAD（中位数绝对偏差）稳健规则** + 领域知识范围三重识别；对输入参数列异常按需线性插值修正，对基准/结果列只标记不篡改；**删除决策必须给出现实/专业依据**（如右尾大任务属正常业务形态→标记不删除）；可加 Winsorize 缩尾对照验证决策稳健性；
  - 一致性：跨表引用完整性（外键∈主表）、单位/口径自洽、物理/业务平衡校验（如电力平衡残差、SOC 边界、功率换算链），输出校验结果。
- **R 代码要点**：`dplyr` + `zoo::na.approx` / `mice::mice`；异常标记用 `abs(x - median(x)) > MAD_MULT * mad(x)`。
- **配图要求**：异常标记前后箱线/分布对比图、缺失分布图（有缺失时）、一致性残差分布图。
- **表格输出**：`step3_异常标记明细.csv`、`step3_一致性校验.csv`、`step3_清洗决策.csv`。
- **场景依据**：合成/真实数据都可能存在"统计异常但业务正常"的行，删除与否必须以现实情况与专业知识为准并写清依据。
- **验收**：删除行数/填补数有明确数值与依据；一致性校验全部通过或有解释。
- **决策点（必须停顿询问用户）**：
  1. 缺失填补方案（中位数 / 插值 / MICE / 删除行）——先给候选方案与理由，用户确认后再执行；
  2. 异常值删除 vs 保留（统计异常但业务正常的行）——先列出标记明细与依据，用户确认取舍；
  3. 有无需按业务口径修正的取值（如单位换算、错值纠正）。

## 第 4 步：数据变换（按需，防泄漏）

- **目标**：对偏度/方差结构不适配后续模型的列做必要变换。
- **必做动作**：偏度诊断（|偏度|>SKEW_THRESHOLD（默认 1）需变换）；右偏用 `log1p`、一般情形可 `Box-Cox`/`Yeo-Johnson`（`car::boxCox` 或手写）、中心化 `scale(center=TRUE, scale=FALSE)`；**必须注明"变换参数在训练集上拟合、再应用到验证/测试集"（防数据泄漏），并给出训练集拟合写法**；|偏度|<阈值 的列说明"无需变换、保留原始量纲"。
- **R 代码要点**：`log1p` / `car::boxCox` / `bestNormalize`；变换参数对象（如 Box-Cox λ、标准化均值/方差）保存并复用。
- **配图要求**：每个变换列"变换前 vs 变换后"双面板图（密度/直方图对比）。
- **表格输出**：`step4_变换决策.csv`（列、原偏度、方法、变换后偏度、采用的阈值）。
- **场景依据**：预测/聚类/进化算法对量纲与分布敏感；但变换要"按需"，避免过度矫正（如均匀分布列变换反而引入偏差）。
- **验收**：变换决策表齐全；变换前后对比图成对存在；防泄漏写法在代码注释中明示。
- **决策点**：|偏度| 恰在阈值附近（0.8–1.2）时，停顿询问是否变换；其余情况按默认阈值自动执行并记录。

## 第 5 步：变量编码与重赋值（重命名）

- **目标**：把分类变量与取值转化为模型可用形式，统一变量命名，修正取值语义。
- **必做动作**：
  - 重命名：列名规范化（小驼峰/下划线、无空格特殊字符）、单位标注（列名或数据字典）；
  - 重赋值：分类取值标准化（如 "Valley/Flat/Peak" 映射为保序标签 0/1/2 或 One-Hot 列；错误取值纠正）；
  - 编码：无序分类→因子+One-Hot（消除伪序）；有序分类→保序标签；数值单位换算（如分钟→小时）也在此步完成。
- **R 代码要点**：`dplyr::rename` / `recode` / `model.matrix(~ . - 1, data)` 或 `fastDummies::dummy_cols`。
- **配图要求**：编码后各分类频数条形图（编码前后对比可选）。
- **表格输出**：`step5_编码映射表.csv`（原取值→新取值/列名）、编码后数据集列。
- **场景依据**：分类变量直接进数值模型会引入伪序；重命名/重赋值保证可追溯与口径统一（对应论文符号表）。
- **验收**：每个分类变量有编码映射记录；One-Hot 后每行恰一个 1；列名与单位自洽。
- **决策点**：取值语义存在歧义（同一含义多种写法、无法判断顺序的分类）时，停顿询问用户映射方式。

## 第 6 步：构造衍生变量（平方项、交互项）与分组分层

- **目标**：从业务机理构造更有表达力的特征，并按关键维度分组分层。
- **必做动作**：平方项、交互项（如 电价×碳强度 耦合指标、GPU×时长=GPU-hour）、业务特征（时长小时化、时延等级、弹性时窗、日内/周时间特征）；按任务类型/区域/时段等分组分层统计并输出组表。
- **R 代码要点**：`mutate` 构造新列；`group_by + summarise` 分组统计。
- **配图要求**：每个核心衍生变量的分布图；交互项散点（按分层着色）；分组柱状/箱线。
- **表格输出**：`step6_分组统计_*.csv`、`step6_分层统计_*.csv`。
- **场景依据**：衍生变量必须来自题目结构/业务机理（如算电协同的"碳-价耦合"），禁止无意义堆特征。
- **验收**：每个衍生变量有定义与图；分组统计表与业务逻辑一致。
- **决策点**：衍生变量候选多时，列出候选清单与动机，询问用户保留哪些（默认保留机理明确且可解释的）。

## 第 7 步：平稳性检验与时间序列预处理（非时序数据可跳过，但须说明）

- **目标**：判断时间序列列是否平稳，必要时差分/季节分解/构造滞后特征。
- **必做动作**：ADF 检验（`tseries::adf.test` 或手写）；不平稳→一阶差分/季节差分；可加 STL/VMD 分解说明；构造滞后特征（预测建模用）；**非时间序列任务明确写"跳过，原因：……"**。
- **R 代码要点**：`tseries::adf.test` / `forecast::ndiffs`；`stats::stl` 分解。
- **配图要求**：时序图、差分前后对比、ACF/PACF（可选）、季节分解图。
- **表格输出**：`step7_平稳性检验.csv`（列、ADF 统计量、p 值、是否平稳、处理）。
- **场景依据**：平稳性假设是 ARIMA 类模型前提；差分/分解避免伪回归；滞后特征提供自回归信息。
- **验收**：ADF 结果表齐全；不平稳列有对应处理；跳过时有原因。
- **决策点**：不平稳且差分会破坏业务含义（如累计量）时，停顿询问采用差分还是水平值建模。

## 第 8 步：多重共线性检验及降维

- **目标**：识别严重共线变量（VIF/条件数）并降维（变量筛选或 PCA）。
- **必做动作**：相关矩阵热力图；VIF（手写 `1/(1-R²)` 或 `car::vif`，>VIF_THRESHOLD（默认 10）严重）；完全共线（派生列）识别；降维：变量筛选（删派生冗余）→ PCA（`prcomp(scale=TRUE)`）输出方差解释与载荷；**PCA/标准化参数在训练集拟合、测试集映射（防泄漏）**；主成分得分可选并入数据集。
- **R 代码要点**：`cor()` + `corrplot`；VIF 手写函数见 `scripts/preprocess_template.R`；`prcomp(scale=TRUE)`。
- **配图要求**：相关矩阵热力图、VIF 条形图（含阈值线）、PCA 碎石图/累计解释率、PCA 双标图。
- **表格输出**：`step8_相关矩阵.csv`、`step8_VIF.csv`（含降维后复检）、`step8_PCA_方差解释.csv`、`step8_PCA_载荷.csv`。
- **场景依据**：共线变量使回归系数不稳、进化算法搜索方向失真；降维保留解释率的同时控制特征数。
- **验收**：VIF 复检全部 <阈值（或说明原因）；PCA 累计解释率报告；防泄漏注明。
- **决策点**：VIF 超阈值列的取舍（删除 vs 合并 vs 留作 PCA 输入）停顿询问；PCA 主成分数由累计解释率自动建议（默认 ≥80%），如与业务冲突询问用户。

## 第 9 步：数据集划分（如需）

- **目标**：划分训练/验证/测试，保证分布一致且无泄漏。
- **必做动作**：时间序列→按时间顺序划分（如训练 0–2351 / 验证 2352–2375 / 测试 2376–2399，禁止随机切分）；非时序→分层抽样（按目标/分组保持比例）或 GroupKFold 防组泄漏说明；划分后输出各集样本量与关键统计。
- **R 代码要点**：时序 `filter(between(hour, ...))`；分层 `caret::createDataPartition` 或手写。
- **配图要求**：时间轴划分着色图（时序）或各类别占比对比图（分层）。
- **表格输出**：`step9_划分_训练/验证/测试.csv`、`step9_划分统计.csv`。
- **场景依据**：随机切分时间序列会泄漏未来信息；分层保证小类别代表。
- **验收**：划分方式与数据性质匹配；各集统计可比性输出。
- **决策点**：划分比例与方式（时间点/比例/是否分层）默认给出方案，用户可覆盖；切分边界（如 2352/2376）必须与题目要求一致。

## 第 10 步：验证处理结果

- **目标**：验证清洗/变换/划分/降维的效果，保证预处理不破坏信息且结论稳健。
- **必做动作**：清洗前后对比（行数/缺失/删除数）；变换前后偏度对比；划分各集均值/波动对比；降维后 VIF 复检；可选：Shapiro-Wilk 正态性、Levene 方差齐性检验；可选：敏感性分析（变换/异常处理选择对关键统计的影响）。
- **R 代码要点**：`summarise` 前后对比；`shapiro.test` / `car::leveneTest`。
- **配图要求**：前后对比柱状/密度图、验证汇总图（每类验证至少 1 图）。
- **表格输出**：`step10_验证_*.csv`（清洗前后/变换前后/划分集/假设检验）。
- **场景依据**：预处理决策必须有量化验证支撑，论文方可引用。
- **验收**：每项验证有数值与图；异常/变换决策的稳健性有对照。
- **决策点**：无停顿；异常/变换决策若被验证推翻，回到对应步骤复验并记录。

## 阈值默认值表（全部可由用户覆盖）

| 参数 | 默认值 | 说明 |
|---|---|---|
| VIF_THRESHOLD | 10 | 多重共线性判定 |
| SKEW_THRESHOLD | 1 | \|偏度\| 超此值需变换 |
| IQR_MULT | 1.5 | IQR 异常规则倍数 |
| MAD_MULT | 3 | MAD 稳健异常规则倍数 |
| PCA_VAR_EXPLAINED | 0.80 | PCA 累计解释率建议线 |
| CV_GROUP | — | 分层划分的目标/分组列 |

覆盖方式：脚本顶部 `# ===== 用户可配置区 =====` 修改变量；交付物中写明"默认阈值 + 实际采用值 + 覆盖理由"。
